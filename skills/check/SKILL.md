# Check

用证据判断“实现是否满足已经确认的契约”。默认只读，不在检查过程中改代码或重写计划。

## 固定比较基点

确定一个比较基点，读取变更相关的 `SPEC.md`、`CONTEXT.md`、Protocol、`AGENTS.md` 和 issue。不要只凭 diff 猜意图。

## 两条检查轴

### 契约

- 目标、边界和 out-of-scope 是否符合 SPEC；
- 概念、身份、关系、生命周期和不变量是否符合 CONTEXT；
- Action Contract 和稳定接口是否符合 Protocol；
- 旧行为是否仍被验证，新行为是否有明确证据。

### 工程

- 测试、类型、错误处理、安全、可访问性和仓库规范；
- 是否有重复抽象、死代码、过早配置或超出切片的改动；
- 是否存在数据丢失、状态泄漏或未覆盖的调用方。

## 输出

每个发现包含位置、影响、复现或证据、建议动作和严重度。区分：

- `blocker`：违反不变量、数据契约或安全边界；
- `required`：SPEC/验收未满足；
- `suggestion`：不影响当前契约的改进。

没有发现时明确写出检查基点、运行过的验证和剩余风险。需要修改时把动作交回 `do`；不要在 `check` 中顺手修复。

如果 issue 有可选的 `evidence_ref`，只判断当前事实是否足以进入
`learn`；不要填写或修改该字段。

## 完成条件

两条检查轴都有结论，验证命令和结果可复核，所有 blocker/required 已关闭或记录，且明确是否可以进入 `learn`。
