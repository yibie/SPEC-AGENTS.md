# Lessons

Use one Markdown file per reusable lesson from a verified failure, surprising
result, or repeated review pattern.

Each lesson should state:

1. trigger and applicable scope;
2. observed failure or pattern;
3. root cause or current interpretation;
4. prevention or preferred practice;
5. verification and source Evidence ID;
6. status, owner, and superseding lesson if any.

A lesson is a scoped warning, not a universal law. If it becomes a durable
invariant or a stable development agreement, promote it through `plan` into
`CONTEXT.md` or `docs/protocols/` rather than silently changing its meaning.
